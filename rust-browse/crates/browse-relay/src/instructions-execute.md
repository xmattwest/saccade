browse drives the user's real Chrome-family browser through the browse extension, accelerated by Saccade's local unified LFM reflex layer. Logins, extensions and open tabs are already there and the user can watch or take over. Run JavaScript with `execute`: it gets `page` (Playwright-style), `context`, `snapshot()`, `ref()`, `handoff()`, `state` and `browse.<tool>()` for every browse tool. `return` a value to get it back; one script can do many steps.

Tabs are the handle. Without `tab`, `page` has no tab until its first `page.goto(url)`, which opens a new background tab. Every execute result starts with `tab: <id>`: pass it as `tab` to your next `execute`, `saccade_act`, `saccade_extract`, or `saccade_sweep` call to keep working in the same tab. Use only tab ids you opened or tabs the user lent (`tabs` lists both).

Prefer Saccade's local fast paths to save time and tokens:
- **Single UI micro-steps (`saccade_act`):** When clicking a button, tab, or filter, or filling one field on an open tab, call `saccade_act({ tab, step, value?, goal? })` directly without pulling a full `snapshot` first. Saccade resolves the ARIA ref and runs its environment-aware pre-CDP Handoff Firewall in a single local pass; if confidence falls below its calibrated threshold, it returns a compact PII-redacted `foveated_snapshot` so you can pick the exact `eXX` ref immediately. Pass `visualFallback: true` on `<canvas>`, chart, or unlabeled-icon views to use Set-of-Marks `[1]..[N]` visual badges.
- **Structured data reads (`saccade_extract`):** When extracting tables, lists, prices, or records into JSON, call `saccade_extract({ tab, schema, focus? })` so the local LFM extracts schema-validated JSON on-device (via zero-token `d1` pointer spans and column alignment) instead of streaming raw DOM text to you.
- **Paginated table & list sweeps (`saccade_sweep`):** When collecting rows across paginated tables or lists (`Next` / `Older` / `Page 2..N`), call `saccade_sweep({ tab, schema, focus?, nextStep?, maxPages? })` to extract, click Next, settle, and deduplicate rows across pages in one local loop with zero per-page cloud round-trips.
- **Multi-step flows & foveated inspection (`execute`):** Compose multi-step sequences inside one `execute` script. When inspecting a large page inside `execute`, pass `await browse.snapshot({ tab, subgoal: "what you need" })` to prune 75-85% of unrelated navbar/sidebar/footer noise in `< 1 ms` (`full: true` returns the unpruned tree). Prefer returned refs (`await ref("e12").click()`), then accessible locators (`page.getByRole(...)`, `getByLabel(...)`), then CSS.
- **Verify:** Always verify state changes with a fresh read (`page.url()`, heading text, or a focused snapshot).

When only a person can proceed (login, 2FA, passkey, captcha, or a destructive/financial mutation paused by the Saccade Firewall), call `handoff("what the user should do")` and wait. Never solve a captcha yourself and never retry-loop a blocked site or a rejected firewall handoff.

The `execute` sandbox runs on the relay, not Node: no require/import, fs, process or fetch (use `page.evaluate` for page JS, `files` for files). Close tabs you opened when finished (`await page.close()`, or `tabs` with action `close`). `status` reports browser connectivity (`nextStep` tells the user how to pair if disconnected), and `saccade_status` reports local LFM memory and trigger telemetry.
